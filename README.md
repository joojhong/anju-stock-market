# 안주주식마켓 (anju-stock-market)

가족(재홍님 + 배우자)의 주식·연금 계좌 잔고, 거래 내역, 평가액 추이를 관리하는 개인용 PWA입니다.
이 문서는 새로운 AI 어시스턴트나 개발자가 이 저장소만 보고도 전체 구조를 이해할 수 있도록 작성되었습니다.

## 한눈에 보는 구조

```
anju-stock-market/
├── index.html          ← 통계/대시보드 홈
├── trading.html        ← 거래 입력
├── history.html        ← 평가액 히스토리 차트
├── setting.html         ← 사용자/기관/상품/계좌/종목 마스터 관리
├── snapshot.html        ← 자동 스냅샷 설정
├── auth.js              ← 로그인/PIN 화면 (아래 "인증 구조" 참고)
├── manifest.json        ← PWA 매니페스트
├── icon-192.png / icon-512.png  ← PWA 아이콘 (manifest.json에서 참조, 확인 완료)
├── apps-script/
│   ├── Code.gs          ← Google Apps Script 백엔드 소스 미러 (라이브 편집기가 원본, 여기는 사본)
│   └── appsscript.json  ← Apps Script 매니페스트 미러
└── README.md            ← 이 문서
```

**⚠️ 이 저장소는 Public입니다.** Drive 폴더 ID, 계정 이메일 등은 아래처럼 의도적으로 가려서 표기합니다. (Sheet/Drive 폴더 자체의 공유 설정은 "제한됨"으로 확인되어 있어 — joojhong 본인 + 가족 2명만 접근 가능 — ID 자체가 공개되어도 직접 접근 위험은 낮습니다. 단 API 관련 사항은 아래 "인증 구조" 참고.)

**⚠️ 레거시 파일 주의**: `history_backup.html`, `auth2.js`, `auth3.js`는 과거 작업 중 생긴 미사용 사본입니다(2026-09-18 GitHub API로 실제 저장소 파일 목록을 직접 조회해 확인). 실제 서비스에 영향 없음, 수정 대상으로 착각하지 마세요.

## 전체 아키텍처

```
[사용자 브라우저 (iOS PWA 포함)]
      │  GitHub Pages: index/trading/history/setting/snapshot.html
      ▼
fetch(GAS_URL + '?action=...')
      │
      ▼
[Google Apps Script Web App]  ← 단일 백엔드 (Code.gs, doGet/doPost)
      │
      ▼
[Google Sheets]  ← 유일한 데이터베이스 (계좌/사용자/금융기관/상품/종목/거래내역/스냅샷/설정/지수)
```

백엔드가 Apps Script 하나뿐이고, Cloud Run이나 Firestore 같은 별도 인프라 전환은 없습니다. 모든 업무 데이터는 Google Sheets 한 곳에 있습니다. Code.gs는 이 시트에 **컨테이너 바인딩**되어 있습니다(코드 내 `SpreadsheetApp.getActiveSpreadsheet()` 18곳에서 확인).

## 배포 구조

| 배포 | 배포 ID | 용도 | 상태 |
|---|---|---|---|
| 배포 A | *(Apps Script 배포 관리 화면에서 확인 — 공개 저장소라 여기 기재하지 않음)* | **GitHub Pages가 실제로 호출하는 운영 배포** | 최신 (버전은 배포 관리에서 확인) |
| 배포 B | *(위와 동일)*, "제목 없음" | 과거 실수로 재배포된 적 있는 미사용 배포 | 미사용, 정리 필요 |
| 배포 C | (미조사) | AppSheet 연동 관련 추정 | 액세스 설정 검토 필요 |

- 실행 계정: `USER_DEPLOYING`(=재홍님 개인 Google 계정) / 액세스 권한: `ANYONE_ANONYMOUS`(모든 사용자, 로그인 불필요)
- **Head 코드를 수정해도 배포는 자동 갱신되지 않습니다.** 배포 관리 → 해당 배포 선택 → "새 버전" → "배포"까지 해야 반영됩니다.
- 프론트엔드(html/js) 수정은 GitHub 커밋만으로 충분 — GitHub Pages가 자동 반영합니다.
- Code.gs를 고칠 때는 항상 Apps Script 편집기에서 재홍님이 직접 붙여넣고 저장/배포합니다. AI가 배포 버튼을 대신 누르지 않습니다.
- 참고: 배포 ID 자체는 이미 공개된 `index.html`/`trading.html` 등의 `GAS_URL` 변수에 그대로 노출되어 있어(보는 사람이 마음만 먹으면 바로 확인 가능), 이 표에서 가리는 건 "굳이 한곳에 정리해서 보여주지 않는" 정도의 의미입니다.

## 캐싱 구조 (2026-09-17~18 추가)

CacheService + PropertiesService 버전 카운터 기반 캐싱이 적용되어 있습니다.

| 대상 | 방식 | TTL | 무효화 조건 |
|---|---|---|---|
| filters / labels / snapshot | `?action=api&type=...` | 300초 | 거래·설정 변경 시 `_invalidateAll()` |
| dashboard(data) | `?action=api&type=data` | 60초 | 위와 동일 |
| readSheet 계좌 | `?action=readSheet&sheet=계좌` | 300초 | 계좌 추가/수정/삭제 시에만 |
| readSheet 거래내역 | `?action=readSheet&sheet=거래내역` | 60초 | 거래 추가/삭제 시에만 |

무효화 키는 항목별로 분리되어 있어(`readsheet_ver_계좌`, `readsheet_ver_거래내역` 등), 거래를 입력해도 계좌 캐시까지 함께 무효화되지 않습니다.

## 인증 구조

`auth.js`는 로그인/PIN 화면을 보여주는 **시각적 오버레이**이며, 실제 인증 게이트가 아닙니다. 데이터 로딩은 PIN 입력 여부와 무관하게 페이지 로드 즉시 진행됩니다.

**중요**: 저장소가 Public이라 `GAS_URL`(Apps Script 웹앱 주소)이 `index.html` 등에 그대로 노출되어 있습니다. 즉 PIN은 화면 오버레이일 뿐 아니라, API 자체도 사실상 인증 없이 열려 있는 상태입니다. Google Sheet와 Drive 백업 폴더는 공유 설정이 "제한됨"(joojhong 본인 + 가족 2명만)이라 직접 접근은 차단되지만, `GAS_URL`을 아는 사람은 이 API를 통한 데이터 조회/쓰기가 이론상 가능합니다. 별도의 API 인증 게이트 도입은 아래 "알려진 이슈"의 백로그 항목 참고 — 가족만 아는 URL이라는 전제로 현재 상태를 유지하기로 결정된 사항입니다(2026-09-18).

## 백업 시스템 (2026-09-18 추가)

'설정' 시트의 `백업_저장시간`(기본 23시)에 맞춰 매일 1회, 구글 드라이브의 지정 폴더(폴더 ID는 이 저장소가 Public이라 여기 기재하지 않음 — Code.gs `백업_상위폴더ID` 상수 참고. 폴더 공유 설정 자체는 "제한됨") 안에 그날 날짜의 하위폴더를 만들고 아래 3가지를 저장합니다.

1. **DB 백업**: 시트 전체를 `DB_YYYY-MM-DD`로 사본 생성
2. **백엔드 백업**: `apps-script/Code.gs`, `apps-script/appsscript.json`을 GitHub raw에서 가져와 저장 (이 저장소의 미러가 최신이어야 의미 있음 — Code.gs 수정 시 반드시 미러도 같이 커밋)
3. **프론트엔드 백업**: `index.html` 등 GitHub Pages 파일 전체를 GitHub raw에서 가져와 저장

보관기간은 15일이며, 지난 날짜 폴더는 `setTrashed(true)`로 **휴지통 이동**됩니다(라이브 코드로 직접 확인 — 완전 삭제 아님). 구글 드라이브 휴지통은 기본적으로 30일 후 항목을 완전히 지우므로, 그 사이에는 실수로 지워진 백업도 복구할 수 있고 휴지통에 있는 동안은 저장 용량도 계속 차지합니다.

Code.gs가 시트에 컨테이너 바인딩되어 있어 스크립트 자체를 `makeCopy()`로 직접 복사하는 방식은 동작이 불확실하다고 판단, 백엔드 백업도 프론트엔드와 동일하게 GitHub raw 방식으로 통일했습니다. Drive 폴더 ID·참조 Sheet ID는 Code.gs 상수에 하드코딩되어 있으며(따라서 이 미러 파일에도 그대로 포함됨), 두 리소스 모두 공유 설정이 "제한됨"으로 확인되어 Script Properties로 옮기지 않고 그대로 두기로 결정했습니다(2026-09-18).

## 알려진 이슈 / 백로그

1. **스냅샷 캐시 무효화 갭**: 시트를 수동 편집하면 스냅샷 캐시가 최대 300초 stale할 수 있음. 후보안 3가지 검토 중(TTL 60초 단축 / onEdit 트리거 / 수동 `_bumpVer` 호출), 미결정.
2. **스냅샷저장 트리거가 특정 버전(32)에 고정됨**: Head가 아니라서 향후 Code.gs를 고쳐도 이 트리거엔 반영 안 됨. 실제 로직 변경 시 트리거의 "실행할 배포"를 Head로 재설정 필요.
3. **doGet/getDashboardData 예외 처리 미비**: 에러 시 HTML 에러 페이지 대신 JSON 반환하도록 개선 필요. (2026-09-18 실사용 중 관련 정황 있음 — 아래 참고)
4. **배포 C의 AppSheet 의존성/액세스 설정 미조사**.
5. **orphan 배포(B) 정리 미완료**.
6. **history.html / setting.html의 일부 순차 fetch**: 병렬화 여지 있으나 효과 작아 보류.
7. **index.html의 `type=indices`(시장 지수)**: 캐싱 미적용, 우선순위 낮음.
8. **2026-09-18 iOS PWA 간헐적 에러**: 통계 화면에 `오류: The string did not match the expected pattern.` 표시된 사례 2건(11:19, 11:21). 해당 시간대 Apps Script 실행 로그엔 실패 기록 없음(서버 예외 아님) / Code.gs엔 `Utilities.parseDate`, `.match()` 사용 없음(그 가설은 기각) / 클라이언트 코드(`index.html`)는 `fetch(...).then(r=>r.json())` 실패 시 `e.message`를 그대로 화면에 표시하는 구조 / 같은 배포 URL을 직접 재요청했을 때 구글 게이트웨이 단계에서 JSON 대신 HTML 에러 페이지가 오는 현상을 실제로 재현함. 앱 완전 종료 후 재실행하면 정상화됨. 원인 후보: ① iOS PWA 캐시/세션 문제(가장 유력) ② 구글 게이트웨이 순간 차단 ③ 네트워크 순간 끊김. 재발 시 정확한 시각·PWA 완전종료로 해결되는지·Safari에서도 재현되는지를 기록해 며칠 관찰 후 재시도 로직 도입 여부 결정 예정 — 미결정.
9. **API 인증 게이트 없음**: 저장소가 Public이라 `GAS_URL`이 공개되어 있어, PIN 오버레이와 무관하게 API 자체에는 별도 인증이 없음. Sheet/Drive 폴더 공유가 "제한됨"이라 직접 접근은 막혀 있지만, API를 통한 조회/쓰기는 이론상 누구나 가능. 현재는 "가족만 아는 URL"이라는 전제로 감수하기로 함(2026-09-18) — 미결정 상태로 남겨둠, 필요시 간단한 토큰 검증 등 도입 검토 가능.

## 배포/롤백 방법

| 고친 파일 | 배포 방법 |
|---|---|
| `*.html`, `auth.js`, `manifest.json` | GitHub 커밋만 하면 끝 (GitHub Pages 자동 재배포) |
| `Code.gs` | Apps Script 편집기에서 재홍님이 직접 수정 → 배포 관리 → 배포 A 선택 → 새 버전 → 배포. 이후 `apps-script/Code.gs` 미러도 같이 커밋 |
| `appsscript.json`(권한 등) | Apps Script 편집기에서 수정 → 저장(권한 범위가 늘면 재승인 팝업이 뜸) → `apps-script/appsscript.json` 미러도 같이 커밋 |

## 보안 정책

API Key, 비밀번호, 실제 Secret 값은 절대 GitHub에 저장하지 않습니다. Script Properties에만 존재합니다. Drive 폴더 ID·참조 Sheet ID는 예외적으로 Code.gs에 하드코딩되어 있으며(따라서 `apps-script/` 미러에도 포함), 두 리소스의 공유 설정이 "제한됨"으로 확인되어 있어 위험이 낮다고 판단해 그대로 두기로 결정했습니다(2026-09-18, 위 "알려진 이슈 9번"과 함께 참고).
